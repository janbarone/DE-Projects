# Master Data Engineer Audit — 2026-08-18

**Audited state:** commit `d325a88` (Rounds 1–20). All high-severity claims verified against the code and the live DB.

**Verdict:** strong junior-portfolio medallion pipeline (sound core: resumable ingestion, bronze upsert loader, silver→gold layering, bridge-fact star schema, single shared runner, deterministic sample data). The orchestration/ops layer is not production-grade and there are data-integrity bugs CI cannot catch.

---

## Priority order — start at P0, work down

### P0 — CRITICAL (data integrity / monitoring)

- **C1. `heroStats` is a frozen snapshot.** `data/_pipeline.py:56-58` dedups `/heroStats` by hero `id` via `update_array_file`, but `/heroStats` is a time-varying aggregate (`pro_pick`/`pro_win`). After the first run every id exists, so it never updates — all win-rate metrics from `stg_hero_stats`/`dim_hero` are permanently stale. Treat as a snapshot (dated files or replace-on-fetch).
- **C2. Incremental silver models never apply source corrections.** All 12 incrementals filter `match_id not in (select match_id from this)` (e.g. `stg_matches.sql:35-37`). The loader upserts bronze (`ON CONFLICT DO UPDATE`), but silver refuses to re-process an existing `match_id`, so OpenDota's re-parsed matches are never propagated; gold stays stale until manual `--full-refresh`. The `unique_key` does nothing (append strategy). `docs/dbt_guide.txt:220-223` claims MERGE semantics that don't exist — wrong doc. Fix: `delete+insert` on `match_id` or `loaded_at` watermark.
- **C3. Freshness monitoring is structurally defeated.** `load_bronze.py:50-51` bumps `loaded_at = now()` on every conflict; the daily job re-loads the same files, so `dbt source freshness` (warn 7d/error 30d) can never fire. Only update `loaded_at` when the payload actually changed; add freshness to all 6 sources, not just `matches`.
- **C4. The scheduled pipeline does not ingest.** Both orchestrators run `load_bronze --data-dir sample_data` (Dagster `definitions.py:26`, Airflow `dota_pipeline_dag.py:47`) — the API scrapers are never scheduled. Daily run = idempotent no-op against static files. Live scrape is 26,712 files vs 4,299 loaded. Point the schedule at `data/` (or wire scrapers in), then backfill.

### P1 — HIGH (ingestion reliability / correctness)

- **H1. Transient API failure permanently drains a league.** `discover_league` (`dota_common.py:266-270`) returns `"unavailable"` for any non-rate-limit failure incl. 503/network; callers `mark_drained(lid)` → a short outage permanently removes the league. Only drain on 404/430.
- **H2. `save_match` stores unvalidated payloads** (`_fetch_matches.py:77-83`) — a 200-with-error-body or empty object is saved and never re-fetched. Phase 2 uses this, phase 1 uses the validating `fetch_match`. Validate `match_id`/`players`.
- **H3. 429 storm aborts the whole run while day quota remains.** After 4 consecutive 429s → `QuotaStop` (live log: stopped with `quota_day=1687` left). Sleep ~60s and resume; cap `Retry-After`; defensively parse quota headers (`_fetch_matches.py:71-74`).
- **H4. Non-atomic file writes + existence-only resume.** `write_json` truncates in place (`dota_common.py:139-143`); `have_match()` checks only `exists()`. A crash mid-write yields a truncated file treated as "have" forever, or corrupts `drained_leagues.json`/`skipped_matches.json`. Use temp-file + `os.replace()`; sanity-check size on resume.
- **H5. `_pipeline.py` executes on import** — module-level code, no `__main__` guard, log unwritten on crash. Add `main()` + always-write summary.
- **H6. Correlated subqueries in gold.** `fact_matches.sql:64-105` runs 6 per-row scalar subqueries against unindexed `stg_match_players` (42k rows) ≈ 4,299 seq scans; `fact_match_player_minute.sql:33-37` does the same over 1.25M rows. Replace with joins/lateral.
- **H7. Unguarded JSON casts abort whole models.** `stg_match_player_damage.sql:23` (`(kv.value)::int`), `stg_match_players.sql:77-78`, and 5+ siblings. One malformed value fails the model. Add a `try_cast` macro.
- **H8. `make_sample.py` destructively deletes the target** (`shutil.rmtree` `:278-280`) with no target≠source guard — `--target data` would nuke the live scrape.
- **H9. Loader: one corrupt file aborts a whole table group** (`load_bronze.py:70`); string/null key drift aborts the group. Per-file error isolation + key casting.

### P2 — MEDIUM (modeling / data quality)

- **M1. Per-minute grain not actually unique (latent).** Raw `times` arrays contain duplicate timestamps (verified: match `1481136585` slot 1 minute 24 twice); no dedupe and no unique test on `(match_id, player_slot, minute)`. Would double-count gold/XP in `fact_match_team_minute`. Dedupe + composite-unique test.
- **M2. No composite-key uniqueness tests anywhere** — `fact_match_players (match_id, player_slot)`, `fact_teamfights (match_id, teamfight_id)`, etc. Add `packages.yml` + `dbt_utils.unique_combination_of_columns`.
- **M3. Relationship tests missing** on `fact_match_player_runes`, `fact_match_player_damage`, `fact_match_player_damage_taken`.
- **M4. Silent `else 'Dire'` side misclassification.** `fact_match_players.sql:141` (+ siblings): null/unexpected `team_number` becomes Dire; `accepted_values` ignores NULLs, so `fact_hero_side`'s side filter is a no-op. Add `not_null` on `team_number`.
- **M5. Text-key tradeoffs.** `fact_team_h2h.sql:21-22` `least()/greatest()` on text team ids → lexicographic pairs (`(10,2)`); `team_a_win` depends on it. Inconsistent rule (`rune_key`/`minute`/`order_no_int` are int). Document exceptions; prefer int keys with text only at the Power BI boundary.
- **M6. Boolean-vs-text literal comparisons** — `fact_match_players.sql:82-83` `is_pick = '1'`; use `is_pick is true`.
- **M7. No model contracts, `{{ doc() }}` blocks, or exposures** — the Power BI model (32 tables/53 rels) is never declared as a dbt exposure; lineage to BI lost.
- **M8. `on-run-end: analyze`** is a blunt global ANALYZE — cheap at this scale, guard failure path.
- **M9. No environment isolation** — `generate_schema_name` = dbt default; dev/CI/prod share `silver`/`gold`. `sources.yml` hardcodes `database: dota`.
- **M10. Migration vs init-SQL drift.** `db/init/*.sql` and the Alembic migration both define bronze, no reconciliation; README's `alembic upgrade head` after a fresh volume fails ("relation already exists"). Add `alembic stamp` step or `IF NOT EXISTS` + a CI diff.

### P3 — LOW (orchestration / CI / reproducibility / ops)

- **O1. Orchestrators are thin BashOperator/subprocess shells** — scheduling + retry flag only. No Dagster `AssetMaterialization`/`RetryPolicy`/`FreshnessPolicy`, no Airflow `execution_timeout`/SLAs, `email_on_failure=False` + no SMTP, deprecated `schedule_interval="@daily"`. Pick one platform and get real value (Dagster assets or dbt-cosmos).
- **O2. Dagster compose profile is broken out of the box.** Image has no dbt; `_find_dbt()` only checks PATH + the host Windows venv mounted into Linux; `db_backed_up` needs `docker exec` but no docker socket mounted.
- **O3. Airflow init is non-idempotent** (`docker-compose.yml:82-85`) — second `up` fails at `airflow users create`; plus `admin/admin` committed, no Fernet key, `_PIP_ADDITIONAL_REQUIREMENTS` installs unpinned ranges on every boot.
- **O4. Dependency pinning is fake.** `requirements.lock` is UTF-16 LE with BOM (verified `FF FE`) → unusable on Linux/CI; referenced nowhere. `dbt-core~=1.12.0` + `dbt-postgres~=1.11.0` mismatch everywhere. Regenerate lock (UTF-8); pin `dbt-postgres~=1.12.0`.
- **O5. CI lint step likely broken.** `.sqlfluff:3` `templater = dbt` but CI installs only `sqlfluff>=3.0` (not `sqlfluff-templater-dbt`, verified absent).
- **O6. CI never tests what matters.** Never calls `run_pipeline.py`, never parses orchestrators, never runs a second build against an existing DB (C2 invisible), never validates `.pbip`/TMDL (manual "184 JSON/474 refs" checks), only exercises 200 sample matches vs 4,299 live.
- **O7. Reproducibility overclaim.** `sample_data/MANIFEST.json:259` commits author's absolute Windows path; Windows venv into Linux containers; `postgres:16` float tag.
- **O8. Ops gaps.** No alerting/monitoring/log retention/backup retention/restore test; no `execution_timeout` on subprocesses (hung `pg_dump` holds the slot); `run_pipeline.py:112/129` hardcodes `postgres/dota`, ignores `DATABASE_URL`.
